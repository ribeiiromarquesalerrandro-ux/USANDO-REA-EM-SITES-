# Conhecimento — juiz

Pesquisado em 2026-10-15. Leia só quando precisar de detalhe.

1. **Registro de decisão (ADR) com 4 partes:** Status, Contexto, Decisão, Consequências (o que fica mais fácil e mais difícil).
   Fonte: https://www.redhat.com/en/blog/architecture-decision-records
2. **Registre só o que é significativo:** afeta estrutura, qualidade, dependências, interfaces; é arriscado, caro ou de efeito longo.
   Fonte: https://csse6400.uqcloud.net/handouts/adr.pdf
3. **Decisão não se apaga: uma nova a substitui** (preserva o histórico).
   Fonte: https://docs.rke2.io/adrs/record-architecture-decisions
4. **Documento curto é lido; documento longo não.** Veredito em poucas linhas, com o porquê.
   Fonte: https://architecture.lullabot.com/adr/20210608-record-architecture-decisions
5. **Condições verificáveis:** cada condição vira um item que o tester confere com comando ou arquivo (mesma lógica do critério Dado/Quando/Então).
   Fonte: https://automationpanda.com/2017/01/26/bdd-101-the-gherkin-language/
